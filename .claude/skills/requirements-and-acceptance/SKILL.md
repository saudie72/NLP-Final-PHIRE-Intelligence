# requirements-and-acceptance

**Purpose:** Make 'done' unambiguous for each feature or change.

**Used by:** Product Manager, ERP Functional Analyst

**Inputs:** A feature or goal.

## Steps

1. Write each story as: As a <role>, I want <capability>, so that <benefit>.
2. Write 2-5 acceptance criteria as Given / When / Then.
3. Name which agent verifies each criterion (qa-tester for app behavior, erp-qa-developer for ERP correctness).

## Output

Requirement with acceptance criteria.
